# ORBIZ POS

ระบบขายสินค้าและสต็อกสำหรับ ORBIZ SOCIAL CLUB ใช้บนไอแพด ทำงานได้โดยไม่ต้องต่ออินเทอร์เน็ต

- เปิดแอปแล้วเข้าหน้าขายทันที ไม่ต้องล็อกอิน พนักงานเลือกชื่อตัวเองก่อนบันทึกการขาย
- พนักงานมี 3 เมนู: ขายสินค้า · ประวัติขาย · ตรวจนับ และปุ่ม ระบบจัดการ (ต้องใส่ PIN ผู้จัดการ)
- ข้อมูลทั้งหมด (สินค้า การขาย รูปสลิป) เก็บในไอแพดเครื่องนั้น สำรองเป็นไฟล์ไว้ใน Files ได้

## ติดตั้งบนไอแพด

แอปนี้เป็น web app ที่ติดตั้งลงหน้าจอโฮมได้ (PWA) ต้องวางไฟล์บนเว็บที่เป็น HTTPS หนึ่งครั้ง หลังจากนั้นใช้แบบออฟไลน์ได้

1. `npm ci && npm run build` ได้โฟลเดอร์ `dist/`
2. อัปโหลด `dist/` ขึ้นโฮสต์ static ที่เป็น HTTPS ตัวไหนก็ได้ เช่น Vercel, Netlify หรือ Cloudflare Pages (ตั้ง build command `npm run build`, output `dist`)
3. บนไอแพด เปิดลิงก์ด้วย Safari → ปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม**
4. เปิดแอปจากไอคอนบนหน้าจอโฮมครั้งหนึ่งขณะมีอินเทอร์เน็ต เพื่อให้แอปเก็บไฟล์ไว้ในเครื่อง หลังจากนี้ปิด Wi-Fi ได้

> ต้องเปิดจากไอคอนบนหน้าจอโฮม ไม่ใช่จาก Safari โดยตรง เพราะ iPadOS อาจลบข้อมูลของเว็บที่เปิดใน Safari ถ้าไม่ได้ใช้นาน 7 วัน แอปที่ติดตั้งบนหน้าจอโฮมจะไม่โดนลบแบบนี้

## ใช้งานครั้งแรก

1. แตะ **ระบบจัดการ** → ตั้ง PIN ผู้จัดการ 6 หลัก
2. **จดรหัสกู้คืน** ที่แสดงหลังตั้ง PIN เก็บไว้ (ใช้ตั้ง PIN ใหม่ถ้าลืม แสดงครั้งเดียว)
3. ตั้งค่า → เปลี่ยนโลโก้เป็นไฟล์จริงของ ORBIZ (PNG พื้นใส)
4. พนักงาน → เพิ่มชื่อพนักงาน
5. สินค้า → เพิ่มสินค้า รูป ราคาขาย ต้นทุน และสต็อกเริ่มต้น

ถ้าอยากลองระบบก่อน: ตั้งค่า → **ใส่ข้อมูลตัวอย่าง** (ใส่ได้เฉพาะเครื่องที่ยังว่าง) แล้วกด **ลบข้อมูลตัวอย่าง** ก่อนเริ่มขายจริง ข้อมูลที่เพิ่มเองจะไม่ถูกลบ

## สำรองข้อมูล

ข้อมูลอยู่ในไอแพดเครื่องเดียว ถ้าเครื่องหายหรือเสีย ข้อมูลหายด้วย ควรสำรองทุกวัน

- ระบบจัดการ → ตั้งค่า → **สำรองตอนนี้** → เลือก **บันทึกไปยังไฟล์** → เลือกโฟลเดอร์ใน iCloud Drive หรือ Google Drive
- ไฟล์ชื่อ `orbiz-pos-backup-YYYY-MM-DD-HHMM.orbizpos` มีทุกอย่างรวมรูปสลิป
- แถบเมนูซ้ายของหน้าขายบอกว่าสำรองล่าสุดเมื่อไร ขึ้นสีเหลืองถ้าเกิน 1 วัน
- ย้ายเครื่อง: ติดตั้งแอปบนไอแพดใหม่ → ตั้ง PIN ชั่วคราว → ตั้งค่า → **กู้คืนจากไฟล์สำรอง** (PIN จะกลับเป็น PIN เดิมในไฟล์)

## ความปลอดภัย

- พนักงานไม่เห็นต้นทุน กำไร หรือรายงาน แก้รายการขายเองไม่ได้ ทำได้แค่ **แจ้งว่ารายการนี้ผิด**
- ระบบจัดการล็อกเองเมื่อไม่มีการแตะตามเวลาที่ตั้ง (ค่าเริ่มต้น 5 นาที) เมื่อสลับไปแอปอื่น และเมื่อกด กลับหน้าขายสินค้า
- PIN เก็บเป็น hash (PBKDF2-SHA256) ใส่ผิด 5 ครั้งล็อก 30 วินาที และนานขึ้นทุกครั้งที่ผิดต่อ
- การยกเลิกบิล ปรับยอดสต็อก อนุมัติผลตรวจนับ กู้คืนข้อมูล ต้องใส่ PIN อีกครั้ง
- ทุกการขายและการแก้ไขบันทึกใน **ประวัติการแก้ไข** ซึ่งแก้หรือลบไม่ได้จากในแอป

ข้อจำกัดที่ควรรู้: PIN ป้องกันการใช้งานผ่านหน้าจอแอป แต่ข้อมูลในเครื่องไม่ได้เข้ารหัส คนที่เอาไอแพดไปต่อคอมพิวเตอร์และรู้วิธีเปิด developer tools อ่านข้อมูลได้ ตั้งรหัสล็อกไอแพด และเปิด Guided Access (การเข้าถึงที่ได้รับการชี้แนะ) ถ้าต้องการล็อกไอแพดให้อยู่ในแอปนี้แอปเดียว

## สำหรับนักพัฒนา

```bash
npm ci
npm run dev        # http://localhost:5173
npm test           # unit tests (Vitest)
npm run build      # build to dist/
npm run e2e        # Playwright: iPad 11" แนวนอน/แนวตั้ง, iPad mini, iPad Pro 13"
```

| โฟลเดอร์ | มีอะไร |
|---|---|
| `src/lib/` | กติกาทั้งหมด ไม่แตะ React: ฐานข้อมูล (Dexie/IndexedDB), การขาย, สต็อก, PIN, สำรองข้อมูล, รายงาน |
| `src/screens/staff/` | หน้าพนักงาน: ขาย, ประวัติขาย, ตรวจนับ |
| `src/screens/backoffice/` | ระบบจัดการ 10 หน้า |
| `src/components/` | ปุ่ม, sheet, keypad, ตัวดูรูป, กราฟ |
| `src/styles/tokens.css` | สี ระยะ ตัวอักษร ทั้งโหมดสว่างและมืด |
| `tests/unit/` | เทสต์กติกา |
| `tests/e2e/` | เทสต์หน้าจอจริงในเบราว์เซอร์ |

กติกาสำคัญที่เทสต์ไว้:

- กดบันทึกการขายซ้ำ/กดรัว ได้บิลเดียว (ทุกออเดอร์มี id ตั้งแต่เริ่ม ใช้บันทึกแบบ idempotent)
- ขายเกินสต็อกไม่ได้ โอนเงินต้องมีรูปสลิป
- ราคาและต้นทุนถูกบันทึกไว้ในบิล ณ ตอนขาย แก้ราคาทีหลังไม่กระทบบิลเก่า
- ยกเลิกบิลคืนสต็อกครั้งเดียว และบิลเดิมยังอยู่ในประวัติ
- ตรวจนับ: ระบบเก็บยอดในระบบ ณ ตอนส่งผล อนุมัติแล้วปรับเฉพาะส่วนต่าง การขายที่เกิดหลังส่งผลยังถูกต้อง
- เงินเก็บเป็นสตางค์ (จำนวนเต็ม) ไม่มีปัญหาทศนิยม
